The scenario

A bank changes its fee calculation with an AI agent

The payments team asks a coding agent to fix a rounding error in card fees, under change ticket CHG-4821. Before the change ships, an auditor asks four questions. This is how well ADP answers each one today.

Who approved this work?

Partly

A grant carries a human-signed approval as its root (ADP-2 G-6), and approval, merge and rulings can never be handed to an agent. A grant missing any limiting field is now rejected (G-10). The signature algorithm is deliberately left for later, so the signature must be present but is not yet checked cryptographically.

How much freedom did the agent have?

Partly

The grant names what the agent may read and write, for one session only (G-3, G-4, G-8). Path matching is now defined exactly, so every tool gives the same answer on whether src/fees/round.py is in scope. What is missing is software that enforces it.

Could the agent change its own controls?

Partly

No grant may let an agent write to its own guardrails: CI, hooks, grant storage (G-7). The overlap test is now defined and errs toward refusing, and a path like src/../ci/hook matches nothing. Enforcement on disk is the runtime's job, and no runtime exists yet.

Can all of this be proven afterwards?

Partly

A report that says COMPLETE while a check failed is rejected, so "done" means every agreed check passed. The instruction and the agent's report can now be checked by software that names the exact rule broken, and that software is itself tested against all 68 published cases. Checking the grant by software comes next. Proving what the agent actually did still needs a runtime, and none exists yet.

#32–#392026-11-26 – 27

Stricter, harder-to-skip checks on ADP itself

A check that cannot find the changes it should look at now fails instead of passing quietly (#33). Checks run after every merge into main and stable, and on release pull requests into stable, not only on ordinary pull requests (#34, #39). ADP uses the same shared commit check as its sister projects, which also checks each pull request's title and description (#38, #37). Dependency updates for the CI actions and the validator arrive weekly as pull requests (#32).

For the bank: a misconfigured check can no longer report "passed" on a CHG-4821 change it never looked at. The stable branch the bank pins to shows its own passing checks after each release, and every CI action is pinned and kept up to date by reviewed pull requests, never by silent upgrades.

#302026-11-26

Security policy, contributing guide and code of conduct

A private channel for reporting vulnerabilities (GitHub private reporting or email), one entry point for contributors, the Contributor Covenant 2.1, and issue forms that ask for evidence the way the defect register does.

For the bank: vendor due diligence finds a published security policy with a private reporting route, so a flaw in the standard reaches the maintainer before it reaches the public.

#292026-11-26

A working validator for instructions and reports (crate 0.1.0, ADP-0 1.3.0)

A Rust library checks every ADP-1 instruction and report and names the exact rule broken and where, for example V-13 at /produce/0/path. CI runs it against all 68 published test cases on every change; a wrong verdict or a right verdict for the wrong reason fails the build. ADP-0 gains an Implementation class: the validator must pass every test case of what it claims, and never overrides the spec. Proposed and accepted in #24.

For the bank: the platform team can embed one validator in front of the agent for CHG-4821. An instruction with a produce entry but no file path is stopped before the agent sees it, and the log says V-13, the rule the auditor can look up. The report that comes back is checked the same way, so a COMPLETE with a failed check never reaches the change record.

#262026-11-22

Routine changes merge without waiting; releases stay with the maintainer (ADP-0 1.2.0)

A contributor may merge into main when checks pass, nothing is asked of the maintainer, no decision is recorded and the change is not security-related. Security-related changes, decisions and releases stay with the maintainer, and releases now live on a protected stable branch. Proposed and accepted in #25.

For the bank: segregation of duties in the standard's own process: the people and agents who write changes cannot ship a release or a change to CI and checks; one named maintainer does, and the bank can pin to stable.

#232026-11-17

Release notes and version tags

CHANGELOG.md lists every version of ADP-0, ADP-1 and ADP-2 with its upgrade impact, and every change since the first commit. Each version has a tag and a pre-release GitHub Release.

For the bank: the policy can pin "ADP-1 1.1.1" to a fixed tag, and the upgrade note says exactly what changes: a COMPLETE report with a failed check is now rejected.

#222026-11-17

The instruction format says exactly what its checks enforce (ADP-1 1.1.1)

Every rule the published schemas apply is now written in the spec, so a validator built from the text gives the same verdict. SOURCE is a field, not a keyword. A COMPLETE report with a failed check is rejected. Tier choice is guidance, with one tie-break rule. Seven defects closed, including all six high ones. Proposed and accepted in #21.

For the bank: the agent's report for CHG-4821 cannot say COMPLETE while "auditor review recorded" is false; it must say BLOCKED and give the reason. A produce entry with no file path is rejected by every vendor's tool, not just some, and the change's origin is always found in one field: source.

#202026-11-17

Every authority check has one exact answer (ADP-2 2.0.0)

Path matching, the guardrail overlap test and how a grant is named in an instruction are now defined exactly. The human-signed record for creating or deleting a repository has a format and its own check. A grant missing a limiting field, or with an expiry outside UTC, is rejected. Five ADP-2 defects closed; ADP-2 has none open. Proposed and accepted in #19.

For the bank: two vendors' tools now give the same verdict on the CHG-4821 grant: src/fees/round.py is in scope, src/../ci/hook is refused, and a grant that forgets its protected list is rejected instead of silently allowing everything. Archiving the old fees repository needs a signed record naming exactly that one repository.

#172026-11-16

Who may ask an agent to do what (ADP-2)

Grants: approval-rooted, session-bound permissions. Creating or deleting a repository needs a human signature scaled to risk. Approval and merge stay human.

For the bank: the change manager issues a grant for CHG-4821: read docs/**, write src/fees/**, today only, with CI and hooks protected. An instruction outside that scope is refused, and the agent cannot open a public repository on its own.

#162026-11-16

Extensions with a fixed home, and typo safety

Teams can add their own fields in one place. Newer-version fields are tolerated; typos in known versions are rejected.

For the bank: x-bank-change-ticket: CHG-4821 rides along without breaking anything. A misspelt ignor: secrets/ is rejected, so an isolation boundary cannot silently disappear.

#142026-11-16

Version numbers checked exactly

Only valid versions of the current major are accepted.

For the bank: an instruction written for a future, incompatible format is refused, so an older system does not misread it.

#122026-11-15

A public set of test cases with known correct answers, checked in CI on every change.

For the bank: procurement can test a vendor's agent tool against the answer key instead of trusting a conformance claim.

#112026-11-15

For the bank: compliance can tell a violation from a recommendation without asking the author.

For the bank: the standard it relies on is itself under audited change control, with every decision traceable to a commit.

What ADP does not do yet

  • The validator covers instructions and reports (ADP-1), not yet grants and authority (ADP-2). It is a library: nothing yet runs it inside an agent runtime.
  • ADP-1 and ADP-2 are Drafts. ADP-2's checks are exact, but no software checks them yet.
  • ADP gives an auditor structured evidence. It does not by itself make a firm compliant with any regulation.
